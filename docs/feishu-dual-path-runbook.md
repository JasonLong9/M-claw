# 飞书双路径联调执行脚本

这份文档用于把飞书接入的两条主路径固定下来，避免联调时只走通一条：

- 路径 A：`新建机器人`
- 路径 B：`关联已有机器人`

目标不是“任选其一能通就算完成”，而是两条都要分别验证。

## 0. 联调前共识

当前 `Mclaw` 的飞书接入要同时满足两类真实场景：

1. 用户没有现成机器人，希望直接在产品里走官方安装器创建。
2. 用户已经有机器人，希望跳过创建，直接把现有机器人接进来。

所以本轮联调的最小要求是：

- `新建机器人` 路径至少完整走一次
- `关联已有机器人` 路径至少完整走一次
- 两条路径都要继续进入后续配对步骤，而不是只做到“按钮能点”

## 1. 共用前置条件

开始前建议先确认：

- `Mclaw` 本地可正常启动
- AI 提供商已配置完成
- 已进入 `连接 IM 渠道 -> 飞书`
- 若要走 `关联已有机器人`，手里要有可用的 `App ID` / `App Secret`
- 若要走 `新建机器人`，建议提前准备飞书扫码环境

## 2. 路径 A：新建机器人

### 目标

验证官方安装器链路是否可用，包括：

- 点击 `新建机器人`
- 安装器启动
- 二维码 / 官方流程可继续
- 新建完成后状态能回到 `Mclaw`
- 能继续进入后续步骤

### 操作步骤

1. 在 `连接 IM 渠道 -> 飞书` 页面点击 `新建机器人`
2. 观察页面是否进入官方安装器流程
3. 若页面显示二维码：
   - 确认二维码已刷新
   - 用飞书扫码继续
4. 完成官方侧创建
5. 回到 `Mclaw`
6. 观察是否出现以下任一成功信号：
   - 检测到飞书机器人配置
   - 可以点击 `完成机器人配置`
   - 可以继续下一步
7. 进入配对页或成功收尾页

### 本路径重点记录

- 安装器是否真实启动
- 二维码是否能稳定刷新
- 新建成功后是否能自动回填
- 是否能无歧义地进入下一步

## 3. 路径 B：关联已有机器人

### 目标

验证已有机器人手动绑定链路是否可用，包括：

- 点击 `关联已有机器人`
- 页面先检查官方插件状态
- 必要时自动补装
- 手填 `App ID` / `App Secret`
- 完成绑定后继续进入配对步骤

### 操作步骤

1. 在 `连接 IM 渠道 -> 飞书` 页面点击 `关联已有机器人`
2. 观察页面是否先做“插件可用性确认”
3. 若插件缺失：
   - 观察是否出现自动补装提示
   - 补装完成后再继续
4. 在手动绑定区域填写：
   - `App ID`
   - `App Secret`
5. 点击 `完成机器人配置`
6. 观察是否出现以下任一成功信号：
   - 检测到已有机器人配置
   - 可以继续输入飞书配对码
   - 成功进入配对页

### 本路径重点记录

- 插件检测是否可靠
- 自动补装是否顺利
- 手动绑定表单是否清晰
- 完成绑定后是否能继续进入配对流程

## 4. 两条路径的共同验收终点

两条路径都不应只停留在“接入表面成功”，还要继续确认：

1. 能进入配对步骤
2. 页面明确建议直接粘贴机器人完整回复
3. 配对页能识别：
   - 配对码
   - 飞书用户 ID（如回复中包含）
4. 至少明确知道当前卡在哪一层：
   - 创建 / 绑定
   - 插件状态
   - 配对

## 5. 建议的执行顺序

建议本轮按下面顺序做：

1. 先跑 `关联已有机器人`
   - 这条路径更适合快速验证已有参数是否能接上
2. 再跑 `新建机器人`
   - 这条路径用于验证完整官方安装器闭环

如果时间有限，也至少要把两条都点进去并走到各自的关键成功提示，不要只验证其中一条。

## 6. 联调结果回填建议

每跑完一条路径，至少记录：

- 走的是哪条路径
- 成功停在哪一步
- 卡住时页面文案是什么
- 是否进入了配对页
- 是否拿到了机器人完整回复

结果可直接按下面文档回填：

- `docs/feishu-integration-result-template.md`

# 飞书联调异常分流表

这份文档用于在飞书真实联调时，快速判断：

1. 当前问题卡在哪一层
2. 先看哪份页面提示或文档
3. 下一步应该继续重试、补参数，还是记录为待修复问题

它不是完整操作手册，而是“出问题时先怎么分流”的快速表。

建议和以下文档一起使用：

- `docs/feishu-live-debug-prerequisites.md`
- `docs/feishu-dual-path-runbook.md`
- `docs/feishu-dual-path-field-record-sheet.md`
- `docs/feishu-integration-result-template.md`

## 1. 快速分流总表

| 现象 | 优先判断层级 | 常见原因 | 第一动作 |
| --- | --- | --- | --- |
| 进不了飞书页 | 入口层 | AI 提供商未完成、前置步骤未走通 | 先回到 AI 提供商确认是否已完成配置 |
| 点击 `新建机器人` 没反应 | 安装器启动层 | 官方安装器未启动、环境异常 | 看飞书安装器输出区与状态卡片 |
| 点击 `关联已有机器人` 后一直转圈 | 插件准备层 | 官方插件未就绪、补装慢、状态未刷新 | 看“路径 B”状态卡与“刷新状态”结果 |
| App ID / App Secret 填了仍不能继续 | 手动绑定层 | 字段不完整、校验失败 | 先看表单错误，再看凭证校验提示 |
| 明明完成机器人配置了却没进配对 | 收尾层 | Gateway 未启动、配置未写回、配对目标未识别 | 先看成功通知，再看控制面板是否出现对应 Bot |
| 进了配对页但总失败 | 配对层 | 配对码错误、没发过消息、跨实例缺少用户 ID | 直接粘贴机器人完整回复，优先让系统识别用户 ID |
| 控制面板里来源显示 `待确认` | 旧配置来源层 | 历史配置未记录来源 | 这是兼容态，不等于当前接入失败 |

## 2. 分阶段异常分流

### A. 入口层

#### 现象

- 还没进入 `连接 IM 渠道 -> 飞书`
- 或进入飞书前就卡住

#### 优先检查

1. AI 提供商是否已完成
2. 当前是否已成功进入 `ChannelConnect`
3. 是否用了远程 OpenAI 兼容服务的可用 `Base URL / API Key / Model ID`

#### 处理建议

- 如果 AI 提供商没完成，先不要排查飞书
- 先把模型配置走通，再回到飞书

## B. 新建机器人路径

### 现象 1：点击 `新建机器人` 后没有进入官方安装器

#### 优先检查

1. 页面顶部“路径 A：新建机器人”状态卡
2. 飞书安装器输出区是否有日志
3. 是否出现“写入飞书官方安装器失败”

#### 处理建议

- 若完全没有输出，记录为“安装器未启动”
- 若已有输出但无二维码，先点一次 `刷新状态`
- 若仍无变化，记录当前最后一条输出

### 现象 2：二维码出现了，但创建完成后页面不继续

#### 优先检查

1. 是否已经出现：
   - `已检测到机器人`
   - `新建机器人已接入`
2. “路径 A”状态卡是否仍在：
   - `创建流程进行中`
   - `等待确认结果`
3. 是否已经可以点击 `完成机器人配置`

#### 处理建议

- 如果只是等待状态没刷新，先点 `刷新状态`
- 如果已看到机器人但不能收尾，记录为“新建后收尾异常”
- 如果页面提示“请先完成飞书机器人创建后再继续”，说明当前仍没识别到新 Bot

## C. 关联已有机器人路径

### 现象 1：点击 `关联已有机器人` 后一直停在准备中

#### 优先检查

1. 页面顶部“路径 B：关联已有机器人”状态卡
2. 当前是否显示：
   - `准备中`
   - `待补全字段`
   - `可直接绑定`
3. 是否有“飞书官方插件尚未就绪”之类提示

#### 处理建议

- 若插件还没就绪，先不要急着填表单
- 优先等状态切到手动绑定，或点 `刷新状态`
- 如果长时间停在准备中，记录当前 notice 文案和状态卡标签

### 现象 2：App ID / App Secret 填完仍无法完成

#### 优先检查

1. 表单是否已有红色字段错误
2. 是否出现：
   - `手动绑定信息未填写完整`
   - `飞书 App ID / App Secret 校验失败`
3. 路径 B 状态卡是否仍为 `待补全字段`

#### 处理建议

- 先按页面字段错误补全
- 若字段齐全但校验失败，优先确认凭证本身，不要误判成插件问题
- 把失败提示原文记录到现场记录表

## D. 收尾层

### 现象：点了 `完成机器人配置`，但结果不明确

#### 优先检查

1. 是否弹出成功通知：
   - `新建机器人已接入`
   - `已有机器人已绑定`
2. 是否出现：
   - `Gateway 启动失败`
   - 或其它收尾错误
3. 控制面板里是否已经出现对应飞书 Bot

#### 处理建议

- 如果有成功通知但还没配对，说明接入层大概率已完成
- 如果没有成功通知且直接报错，优先记录收尾报错
- 如果控制面板无对应 Bot，记录为“接入写回异常”

## E. 配对层

### 现象 1：输入配对码后提示未找到请求

#### 优先检查

1. 是否只输入了一串配对码
2. 是否粘贴了飞书机器人完整回复
3. 页面是否已识别飞书用户 ID

#### 处理建议

- 优先直接粘贴完整回复
- 如果系统已识别用户 ID，会自动尝试兜底授权
- 若仍失败，记录：
  - 是否触发兜底
  - 最终错误提示

### 现象 2：提示配对码过期

#### 处理建议

- 回到飞书重新给机器人发消息
- 获取新回复后重新粘贴
- 不建议继续只复用旧配对码

### 现象 3：页面提示网络或系统错误

#### 处理建议

- 先排除当前实例是否异常
- 记录是否为偶发错误，还是稳定复现
- 若稳定复现，再继续看 Gateway / CLI / 插件侧

## F. 控制面板回看层

### 现象 1：控制面板里显示 `已接入，待配对`

#### 含义

- 接入层已基本成功
- 但还没有用户完成配对

#### 下一步

- 继续进入配对页完成用户配对

### 现象 2：控制面板里显示 `已接入并已配对`

#### 含义

- 接入层和至少一个用户配对都已成功

#### 下一步

- 可视为该 Bot 最小闭环已完成

### 现象 3：控制面板里显示 `来源：待确认`

#### 含义

- 这通常是旧配置
- 不是当前这次接入失败

#### 下一步

- 参考 `docs/feishu-source-migration-strategy.md`
- 不要直接把它判断成新问题

## 3. 记录建议

当你现场卡住时，至少记录这四项：

1. 当前走的是哪条路径
   - 新建机器人
   - 关联已有机器人
2. 当前卡在哪一层
   - 入口
   - 创建/绑定
   - 收尾
   - 配对
   - 控制面板回看
3. 页面最后一条关键提示是什么
4. 是否已经出现对应 Bot 卡片

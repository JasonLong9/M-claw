# Mclaw 功能边界表

## 1. 边界目的

本表用于防止开发过程中范围漂移。  
判断规则分为四类：`v1 必做`、`v1 预埋`、`v1.5`、`v2+ 再做`。

## 3. 功能进入 v1 的判断条件

必须同时满足以下条件才可进入 v1 主线：

1. 直接影响安装、接入、稳定运行或安全边界。
2. 能基于现有仓库能力低风险扩展。
3. 不依赖服务端或复杂商业系统。
4. 不会因为平台差异导致后续大面积返工。

## 4. 延后处理规则

以下情况应自动延后到 v1.5 或 v2：

1. 需要新增服务端系统。
2. 需要支付、结算、分销、邀请码运营后台。
3. 会显著拖慢 v1 的安装与接入主流程。

# hizeys 看门狗代码合并门槛

更新日期：2026-04-10

## 1. 目的

这份文档只回答一个问题：

- `hizeys` 分支里的 watchdog 代码，**什么时候可以正式合并进当前主线**。

结论先说：

- **不是现在**
- **要等当前本地直聊主链路稳定后再合并**

这里的“稳定”不是主观感觉，而是必须满足下面的明确门槛。

## 2. 当前为什么还不能直接合并

当前主线的核心阻塞仍然是：

1. `gateway` 启动后的 readiness 确认仍存在 legacy 假阴性；
2. 模型已保存后，`Direct Chat` 首条消息发送链路仍需要继续稳定验证；
3. 当前更急的是把“用户第一次启动 -> 配模型 -> 启动网关 -> 发出第一条消息”这条主链路跑顺。

而 watchdog 解决的是：

1. 网关挂掉后能否自动发现；
2. 发现后能否自动恢复；
3. 连续失败时能否熔断与记录事件。

所以当前阶段如果直接合并 watchdog，本质上是：

- 在主链路还没完全稳定前，先做“异常后的自动恢复”

这会打乱优先级。

## 3. 允许合并 watchdog 的阶段定义

只有当项目进入下面这个阶段，才建议把 `hizeys` 的 watchdog 主体正式并入主线：

- **阶段名称：稳定性增强阶段**

进入该阶段的标志是：

1. 当前主要问题已经不再是“能不能聊天”；
2. 当前主要问题开始转向“挂了以后怎么自动恢复、怎么更稳”；
3. 本地直聊闭环已经具备可重复验证的成功率。

## 4. 必须满足的合并门槛

以下 5 条必须同时满足，才可以把 watchdog 主体并入主线。

### 4.1 网关启动门槛

必须满足：

1. 用户点击“启动网关”后，不再长期停留在：
   - `Gateway 尚未完成就绪确认`
2. 至少在当前主测环境（Windows）上，网关启动状态能稳定收敛到：
   - 可确认可用
   - 或明确失败原因

不满足这条时，不应合并 watchdog。

原因：

- watchdog 不是拿来替代当前 readiness 修复的。

### 4.2 模型生效门槛

必须满足：

1. 模型添加、保存、切换后，页面状态与本地配置保持一致；
2. 会话侧读取到的模型与设置页已保存模型一致；
3. 不再频繁出现“模型看起来保存了，但会话不可用”的主线故障。

不满足这条时，不应合并 watchdog。

原因：

- 如果模型链路还不稳，看门狗恢复也无法证明聊天链路真正可用。

### 4.3 首条消息发送门槛

必须满足：

1. 在当前 Windows 主测环境下，可以完成：
   - 打开应用
   - 配置模型
   - 启动网关
   - 发送第一条消息
   - 收到真实返回
2. 连续多轮测试中，首条消息发送成功率达到可接受范围。

建议验收标准：

1. 同一构建版本下，连续 `10` 次发送测试，成功不少于 `8` 次；
2. 若失败，失败原因应明确可分类，而不是卡死或无反馈。

### 4.4 主阻塞收敛门槛

必须满足：

1. 当前 backlog 的最高优先级问题，不再是：
   - 网关起不来
   - 会话发不出去
   - 模型配置不生效
2. 当前 backlog 的最高优先级问题开始变成：
   - 网关偶发退出
   - health check 不够稳
   - 自动恢复不足
   - 熔断与事件留痕不足

只有到这个时候，watchdog 才是正确的下一步。

### 4.5 工程验收门槛

必须满足：

1. `npm run typecheck` 持续通过；
2. 当前主线打包版可正常启动；
3. 当前工作不再依赖大量临时兼容兜底才能进入对话；
4. watchdog 合并后不会掩盖主链路真实问题。

## 5. 当前阶段判断

截至 `2026-04-10`，当前判断如下：

1. **还没有达到 watchdog 主体的正式合并门槛**；
2. 当前项目仍处于：
   - 本地直聊主链路稳定化阶段
3. 当前最应该继续完成的任务仍然是：
   - 模型保存与会话生效一致性
   - 网关 readiness 判定稳定化
   - Direct Chat 首条消息发送闭环验证

因此当前策略应为：

1. watchdog 文档先明确；
2. watchdog 分支先保留；
3. 主线先继续完成当前阻塞项。

## 6. 现在可以先合什么

虽然 watchdog 主体现在还不建议整包合并，但以下内容可以先吸收：

1. `6f5ac4c`
   - `electron/main/cli.ts`
   - Windows 下 `.cmd/.bat/.ps1` 自动启用 `shell`

这是低风险、底层、对当前 Windows 主线直接有帮助的修复。

而以下内容不建议现在跟随整包并入：

1. `d722888`
   - 未签名构建策略调整
2. `2da10bf` + `2a67e8a`
   - watchdog 主体

## 7. 达到门槛后的推荐合并方式

等满足门槛后，仍然不建议“无条件一把梭”直接合并，而建议按下面顺序：

1. 先合低风险底层修复；
2. 再把 watchdog 主体以 feature 方式接入；
3. 初期默认关闭或仅诊断开关开启；
4. 补齐：
   - 恢复阈值
   - 超时控制
   - 事件持久化
   - 与 gateway lifecycle controller 的统一状态源
5. 最后再决定是否默认启用。

## 8. 一句话标准

只有当项目已经从：

- “先把聊天跑通”

切换到：

- “聊天已经基本稳定，开始做异常恢复与韧性增强”

才可以正式合并 `hizeys` 的 watchdog 主体代码。
